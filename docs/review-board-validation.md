# 审核修复的上板验证

本次修复采用构建检查、调用链核查和目标板验证；未使用 test/tests，未烧录或操作硬件。

## 改动边界

- 保留云台上电配置角度、遥控失联保持目标角度的行为。
- 保留控制周期、传感器采样频率、初始化寄存器等待及 CAN 自动重传配置。
- 标定仍要求机构静止。控制空闲只表示软件目标/输出为零，不能证明机构物理静止。
- 保存前由 Motor 任务停止更新运动目标，清除 DJI 目标和 PID 输出，发送 DM 失能命令；等待旧邮箱排空，并确认完整停机批次获得硬件 TXOK。
- 已有 DM 反馈还必须处于失能状态且未超过 50 ms。CAN 未获得应答、邮箱未排空或发送失败时，100 ms 内无法确认就中止保存，回执为 `cal:abort,stop_timeout`。
- TXOK 仅证明 CAN 帧发送成功，不证明每台电机都已执行；标定保存应在机构已固定、无需主动保持力矩的台架条件下进行。
- 擦写时锁定任务调度并关闭加热 PWM，结束后恢复调度。DJI 沿用反馈超时门控；DM 目标缓存和速度模式已清除，只有应用重新设置速度目标或显式使能后才会启动。
- 未接 CAN 设备、没有节点 ACK 时，本版本不会执行运行期 Flash 保存。

## 验证项目

| 场景 | 观察位置 | 通过条件 |
| --- | --- | --- |
| 正常启动，有/无已存零偏 | `Attitude_Bias_Source`、`Attitude.GyroBias`、`BSP_BMI088.Get_VQF_Reset_Counter()` | 零偏初值被采用；解算从新队列开始，不因启动残留队列产生额外断流重置 |
| 在线标定 | USB 文本、`s_Cal_State`、`maintenance_requested`、`maintenance_ready` | 开始回执可见；停机批次 TXOK 后才进入保存；结束回执可见 |
| 控制活跃时请求标定 | 电机目标/输出、USB | 拒绝标定，保持原有控制行为 |
| 停机确认时 CAN 无 ACK 或持续仲裁失败 | CAN 分析仪、发送计数、USB | 不擦 Flash，超时回执可见；恢复总线后可重新请求标定 |
| 保存期间 | CAN 分析仪、TIM10_CH1、逻辑分析仪 | 保存前停机指令已发出；保存期间无新运动指令，加热占空比为零；记录实际控制间隔和擦写耗时 |
| 超过 100 ms 的受控 IMU 断流 | VQF 重置计数、零偏、姿态有效标志 | 断流使姿态过期；恢复时零偏保留，姿态参考按现有重置行为重新建立 |
| 无效陀螺样本，单次和连续 | 在 `Calculate()` 取样后用调试器将本地 `gyro_sample.Valid` 置零，再继续运行 | 不推进滤波器或有效时间戳；姿态无效，在线标定中止；正常样本恢复后重新发布有效结果 |
| USB 忙或未连接 | `s_USB_Pending_Length`、USB 文本 | 最新回执保留，恢复发送后消费；同轮不发送姿态波形争抢端点 |
| 满配 CAN 总线 | 按 ID 记录频率和最大间隔 | 实测带宽、最长更新间隔和故障计数，不能以“邮箱提交成功”代替测量 |

新 CAN 观测量：`can_tx_submit_count`、`can_tx_complete_count`、`can_tx_arbitration_lost_count`、`can_tx_error_count`、`can_rx_overrun_count`。计数为累计值，比较同一测量区间的增量；系统空闲时，成功完成数应追上提交数。一个溢出计数表示观测到一次 FIFO 溢出事件，不等于精确丢帧数。

调试器暂停会改变实时行为；停机发送和 Flash 时序以 CAN 分析仪及 GPIO/逻辑分析仪观测为准，不以断点暂停期间的反馈超时作为故障证据。

`Attitude` 已限制在 `sys_attitude.cpp` 内，生产代码统一通过 `Attitude_Get_Snapshot()` 读取。调试器若无法直接解析 `Attitude.GyroBias`，需使用其文件限定名；不要为观察重新公开该对象。

## 性能建议的后续验证

先分段测量 BMI088 初始化、Motor 执行时间和周期抖动、IMU `Calculating_Time`、队列高水位及丢样。可比较现有 Debug 与 Release，但构建体积和编译选项不能替代运行耗时测量。只有取得基线并核对器件时序后，再缩短寄存器等待、删减派生量或调整通信频率。

## DM4310 主控速度 PID

`system_init.cpp` 中 `DM4310_Motor_Create` 最后三项为 STM32 上 `Class_PID` 的 Kp、Ki、Kd。输入为 rpm，输出为 N·m，计算周期为 1 ms，积分输出和总输出均限幅 ±T_MAX。参数以当前创建实参为准。换算参考：Kp=0.10472、Ki=Kd=0 时，比例作用约等效原内置 MIT Kd=1，并不代表实际机构已完成调参。原来的双参数速度接口已移除；直接 MIT 控制仍用 `Set_Target_MIT()`。

在 `Motor_Task` 正常控制分支中取得 `DM4310_Motor_Get(0x05U)`，通过 `Set_Target_Speed_Rpm(rpm)` 设置速度，由现有 `DM4310_Motor_Control_Task()` 自动发送使能命令，收到新鲜的使能反馈后运行 PID。不需要应用额外调用 `Enable()`；直接 MIT 模式仍需显式使能。初始化本身不发送使能指令。

| 上板场景 | 观察与通过条件 |
| --- | --- |
| 上电后设置速度目标，无额外使能调用 | 周期控制先发送使能帧；反馈 State=1 且未超时后，PID 开始输出扭矩；等待期间不累积积分 |
| 分别设置 +5、0、-5 rpm | 反馈 `Velocity_Radps * 60 / (2π)` 跟随目标；零速目标仍为闭环制动，失能停机用 `Disable()` |
| 检查速度模式 CAN 帧 | 位置、速度、Kp、Kd 的物理目标均为零，仅扭矩字段承载 PID 输出；`Get_Target_MIT()` 只表示直接 MIT 目标，不表示速度环输出 |
| 带负载调参 | 先调 Kp；确有稳态速度误差再增加 Ki。观察速度误差、积分和输出扭矩；积分与输出不超过 ±T_MAX |
| 无反馈、反馈超过 50 ms 或失能状态 | 速度 PID 清历史并重发使能；有效使能反馈恢复前不输出控制扭矩，恢复后按保留的速度目标重新闭环 |
| 新鲜反馈为故障状态 | 速度 PID 清历史并提交零扭矩，不自动发送清错命令 |
| 无效速度目标 | NaN 或无穷大不触发使能，速度 PID 清历史并提交零扭矩 |
| 控制模式切换和维护停机 | 切换时清 PID 历史；`Disable()` 清两种目标、PID 输出和历史并退出速度模式，后续单独调用周期控制不会使能。维护期间不设置速度目标；维护结束后应用重新设置速度目标会再次启动 |

调试器暂停会触发反馈超时；恢复和时序判断以连续运行时的观测为准。本次仅执行构建和调用链检查，上述实机步骤待上板验证。
